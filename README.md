# AOI 業務/評估/詢價系統

免費架構：**Google 試算表(資料庫) + Google Apps Script(後端 API) + GitHub Pages(前端網頁)**

不需要租主機、不需要付費資料庫，只需要一個 Google 帳號。

---

## 整體架構

```
使用者瀏覽器
    │  打開 GitHub Pages 網址 (前端網頁)
    ▼
GitHub Pages（frontend 資料夾）
    │  網頁上的按鈕，透過 fetch() 呼叫下面的網址
    ▼
Google Apps Script Web App（apps-script 資料夾，部署後得到一組 exec 網址）
    │  在這裡讀寫資料、產生 PDF/WORD、寄信
    ▼
Google 試算表（你自己建立，當作資料庫）
```

前端（GitHub Pages 上的網頁）**完全不會拿到、也不需要知道任何密碼**，
所有帳號密碼比對、Google 試算表存取，都是在 Apps Script（後端）裡執行，外部看不到。

> **快速安裝（三個動作）**：貼上程式 → 執行 `setup` → 部署。分頁、欄位、設定、附件資料夾、管理員帳號都會自動建立，不用手動建表。

## 第一步：建立試算表並貼上後端程式

1. 到 Google Drive 新增一個 Google 試算表，命名例如「AOI系統資料庫」
2. 在試算表選單「擴充功能」→「Apps Script」
3. 把本專案 `apps-script/Code.gs` 的內容整個貼進去（覆蓋預設的 Code.gs），按儲存
4. 左側「專案設定」齒輪 → 勾選「在編輯器中顯示 appsscript.json」→ 回到編輯器打開 `appsscript.json`，把本專案 `apps-script/appsscript.json` 的內容整個貼進去覆蓋，按儲存

> 也可以直接建一個獨立的 Apps Script 專案（script.google.com → 新專案）貼上程式，`setup` 會自動幫你建一份「AOI系統資料庫」試算表。

## 第二步：執行 setup（自動建立所有分頁）

1. Apps Script 編輯器上方的函式下拉選單選 **setup** → 按「**執行**」
2. 第一次會跳出授權視窗：選你的 Google 帳號 →（如果出現「Google 尚未驗證這個應用程式」，按「進階」→「前往（不安全）」）→ **允許**
3. 下方「執行紀錄」會列出做了哪些事，其中一行是：
   ```
   ★ 已建立管理員帳號 ── 帳號：admin　密碼：xxxxxxxxxx
   ```
   **把這組密碼記下來**，這是第一次登入用的帳號

setup 會自動：
- 建立 16 個分頁（Products / PriceHistory / Cases / CCDRequirements / CaseCompanies / Staff / Customers / CustomerContacts / ContactLogs / Users / Config / Devices / Favorites / Shortcuts / Memos / Software）與所有欄位，標題列加粗凍結
- 電話、精度（`+2` / `-2` / `±2`）、帳號等欄位設成純文字，避免試算表把 `0912…` 的 0 吃掉、把 `-2` 變成負數
- 在 Config 分頁加上範本 ID等設定（值留空，需要時再填）
- 在雲端硬碟建立「AOI系統附件」資料夾
- Users 分頁沒有任何帳號時，建立管理員 `admin`（隨機密碼）
- 設定每 10 分鐘自動喚醒一次（`keepWarm`），減少網頁第一次操作要等好幾秒的情況
- 匯入舊資料 `data.xlsx`（55 間公司的聯繫紀錄）到 Customers / CustomerContacts，只補「還沒有的公司名稱」，重複執行不會重複匯入、也不會覆蓋你之後手動改過的內容。因為含客戶個資，資料放在本機的 `apps-script/ImportData.gs`（已加入 .gitignore，不會推上公開的 GitHub）：在 Apps Script 編輯器「檔案 +」新增一個 `ImportData` 檔案，貼上它的內容再執行 setup 即可；沒貼這個檔案就只是略過匯入

> **可以重複執行**：已經存在的分頁只會補上缺少的欄位（加在最後面），不會刪資料、不會改順序、不會重複建帳號。之後程式更新有新欄位時，貼上新版 Code.gs 再執行一次 setup 就好。
> 程式綁在試算表上時，打開試算表會多一個「**AOI 系統**」選單，也可以從那裡執行 setup。

## 第三步（選填）：建立需求單 / 評估單 / 報價單的 Google 文件範本

> 只用 **HTML** 格式輸出的話可以整段跳過。要輸出 PDF / Word 才需要範本。


分別建立兩份 **Google 文件**（不是上傳 Word 檔，是直接在 Google Docs 建立），
在文件內容裡打上「佔位符」，程式會自動把它們換成真正的資料。

**需求單範本可用的佔位符：**
`{{CaseID}}` `{{CustomerName}}` `{{Salesperson}}` `{{FAE}}` `{{RequirementDetails}}` `{{Date}}`

**評估單範本可用的佔位符：**
`{{CaseID}}` `{{CustomerName}}` `{{FAE}}` `{{TestResult}}` `{{RecommendedProduct}}` `{{Tester}}` `{{TestDate}}` `{{Notes}}`

**報價單範本比較特別，除了文字佔位符，還需要放一個「表格」：**

抬頭文字用佔位符：`{{CustomerName}}` `{{QuoteDate}}` `{{QuoteType}}` `{{Total}}`

接著在文件裡插入一個表格，結構如下（用 Google 文件選單「插入 > 表格」）：

| 品名 | 數量 | 單價(報價) | 小計 |
|---|---|---|---|
| (範例列，內容隨便打，例如「範例品項」「1」「0」「0」) | | | |

程式會把「表格最後一列」當作範本，依你加入的品項數量自動往下增加列數並填入資料，
原本那個範例列最後會被程式自動移除，所以範例列內容打什麼都沒關係，但**欄位順序一定要是：品名、數量、單價、小計**，且只能有這一個表格。

範本文件排版（字型、Logo、表格、抬頭）你可以自己排，程式只負責換文字，格式會照範本呈現。

建立好後，從網址列複製文件 ID：
```
https://docs.google.com/document/d/【這一段就是文件ID】/edit
```
把兩個 ID 分別貼到試算表 Config 分頁對應的 Value 欄位。

## 第四步：新增其他登入帳號（選填）

用 admin 登入後，到導覽列「系統 → 帳號管理」直接新增帳號、選角色、重設密碼、刪除，不用再手動改試算表：

四種角色（只有系統管理員看得到帳號管理頁）：

| 角色 | 能做什麼 |
|---|---|
| **系統管理員**（admin） | 全部功能，**可以刪除**，管理帳號、人員、登入紀錄與系統設定；至少保留一位，也不能把自己降級 |
| **編輯者**（editor） | 全部業務功能可新增、修改；**不能刪除**、不能管理帳號 |
| **查看**（viewer） | 全部業務功能唯讀（個人資料、改密碼、常用型號、備忘錄等個人功能照常） |
| **特定**（limited） | 只開放勾選的功能區塊（產品與詢價／案件管理／客戶與行事曆／檔案製作／文案製作／BOT 設定），每個區塊各自選「查看」或「編輯」，不能刪除；有「業務助理、報價專員、客服小編、文案小編、全部只查看」快速套用 |

- **刪除只有系統管理員**，而且伺服器端檢查：編輯者用工具直接送出刪除請求也會被拒絕；畫面上其他角色看不到刪除按鈕、沒權限的選單會隱藏、沒權限的頁面進去只會看到說明、只能查看的頁面上方有提示。
- 每個後端動作都登記「屬於哪個功能區塊、要查看還是編輯」（`Code.gs` 的 `ACTION_PERM`），沒登記的動作預設只有系統管理員能用；新模組（Bot.gs、Copy.gs）在自己的 `botPerms_()` / `copyPerms_()` 登記。
- 改角色、改權限在對方**下一次操作就生效**（每次都即時查 Users 分頁）。
- **舊角色**：原本的 `sales`（業務，可刪除客戶 / 案件 / 產品等）、`fae`（工程，不能刪除）在你按「遷移舊角色」之前維持原本的權限，只是不能用新的 BOT 設定與文案製作；按「遷移舊角色 → 編輯者」後全部變成編輯者（業務原本的刪除權限會沒有，之後只有系統管理員能刪除）。也可以在列表裡個別改角色。
- Users 分頁新增 `Perms` 欄（「特定」角色的權限 JSON），重新部署後執行一次 `setup` 會自動補上。

密碼留空會自動產生亂數密碼，只會在新增/重設那一刻顯示一次（系統只存雜湊值，不存明文）。想調整某個動作要什麼權限，改 `Code.gs` 的 `ACTION_PERM` 就好。

## 第五步：部署成 Web App

1. Apps Script 編輯器右上角「部署」→「新增部署作業」
2. 類型選「網頁應用程式」
3. 「執行身分」選「我」，「具有存取權的使用者」選「所有人」
4. 按「部署」，會出現一組網址，長得像：
   `https://script.google.com/macros/s/xxxxxxxxxxxx/exec`
5. 複製這個網址

> 之後如果你有修改 Code.gs，要用「管理部署作業」→ 編輯（鉛筆）→ 版本選「新版本」→ 部署，網址不變但會套用新程式碼。

## 第六步：設定前端並發布到 GitHub Pages

本專案已經附好自動部署設定（`.github/workflows/pages.yml`），整個專案推上 GitHub 後會自動把 `frontend` 資料夾發布成網站，不用手動上傳檔案。

1. 打開本專案 `frontend/config.js`，把 `API_URL` 換成第五步複製的網址
2. 到 GitHub 新增一個 **Public** repository（前端本來就是公開網頁；README / .gitignore 都不要勾，保持空的）
3. 把整個專案推上去（`git push`）
4. 進入 repo 的 **Settings → Pages → Build and deployment → Source** 選 **GitHub Actions**
5. 到 repo 的 **Actions** 分頁，等「部署前端到 GitHub Pages」變成綠色勾勾（第一次如果在第 4 步之前就跑失敗了，點進去按 **Re-run all jobs**）
6. 網址會是 `https://你的帳號.github.io/repo名稱/`（Settings → Pages 最上面也看得到），打開會先看到登入頁，用第二步 setup 產生的 admin 帳密（或第四步新增的帳號）登入
7. 之後改了 `frontend` 裡的檔案，只要 commit + push，網站約 1 分鐘內自動更新；改了 `apps-script/Code.gs` 則要照第五步重新部署 Apps Script

## 日常使用方式

- **業務**：在「產品搜尋/詢價」分頁查型號、看上次報價、產生詢價信文字（有設定 Gmail 會自動建草稿）；一進分頁就會列出全部產品，打字會即時篩選（0.3秒後自動查，不用按搜尋按鈕，按 Enter 也可以）；產品可以直接新增/修改/刪除，多了「產地」欄位跟「類別」下拉選單（相機/調光器/光源/線材/工業主機/軟體包/其他），底價/牌價互相輸入自動換算，備註也會直接顯示在搜尋結果跟詳情裡；價格歷史紀錄也能個別編輯或刪除
- **軟體名稱下拉選單**：案件的「軟體名稱」從 Software 分頁的清單選（點欄位或打字會列出選項）。輸入清單裡沒有的名稱、按建立/儲存案件時，會問「此名稱不在軟體名稱資料庫內，是否新增？」，選「確定」就加進清單並繼續存檔，選「取消」則不存檔。`setup` 會把既有案件用過的軟體名稱自動補進清單；admin 可到「系統 → 人員管理」頁最下面的「軟體名稱清單」直接新增/刪除
- **首頁（登入後第一頁）**：① 常用網站——按「編輯」加入自己常用的網站（網址不用打 https://），勾「預設開啟」的網站，之後上班按一下「▶ 一鍵開啟預設網站」就全部開好（瀏覽器如果擋掉第二個以後的分頁，網址列會出現「已封鎖彈出式視窗」，選「一律允許」本網站即可）；② 我的行事曆——**每個帳號各自的內建行事曆**（今天 / 7 天 / 30 天，含別人分享給你的），每筆可按「存成備忘」；③ 工作清單小卡——未完成的前 8 項、勾選就完成、上方輸入框按 Enter 快速新增；④ 常用型號；⑤ 備忘錄——預設只有自己看，可選分享給「指定的人 / 自訂群組 / 全部同事」，別人分享的只能看，只有建立者（或 admin）能改、刪。常用網站、常用型號、備忘錄都是每個帳號各自一份（Shortcuts / Favorites / Memos 分頁）
- **常用型號**：「產品搜尋」每個產品前面有 ☆，按一下加入常用（★），勾「★ 只看常用」就只列自己的常用產品
- **型錄匯入與資料提醒**：`setup` 會自動把「選型計算」型錄（GigE / USB3 相機、FA 鏡頭、遠心鏡頭，約 99 筆）讀進 Products，規格摘要寫在備註；之後在「產品搜尋」按「匯入型錄產品」也能隨時補抓（只新增還沒有的，不會動已有的）。型錄沒有價格，所以匯入後列表會標出「缺內部型號 / 缺底價 / 缺供應商 / 缺詢價信箱」的提醒，可勾「只看資料不完整的」集中補資料，內部型號空白的產品也能用「編輯此產品」補上。每筆產品都記錄「上次修改日期」（Products 的 `LastUpdated`），並顯示上次詢價日期；超過 90 天沒更新會標示「建議重新向原廠詢價」，由你自己判斷要不要再詢價。型錄 ID 預設用 config.js 那份，要換可在 Config 分頁加 `CatalogSheetId`
- **德鴻官網規格匯入**：「產品搜尋」頁按「匯入德鴻官網」，會從 twdehong.com 把能抓到的規格全部讀進來（約 2100 筆，3～5 分鐘；**不含價格**）：遠心鏡頭與機器視覺鏡頭（含各靶面視野）、光源、光源控制器、光學棱鏡、相機（Hikrobot 海康 / FLIR / Basler / MindVision 等，含官網規格表與商品內頁）、海康讀碼器與智慧相機、DHC FA 鏡頭系列、液態鏡頭，官網全部 1498 個商品頁都已涵蓋（同型號在不同分類重複出現時只留一筆）；官網沒有的：價格、應用參考頁、圖片與型錄 PDF。官網的商品內頁內容與分類列表相同，所以不用逐頁進去抓。內部型號與供應商型號先用德鴻型號，供應商填「德鴻」，詢價信箱帶官網的 TWDH@twdehong.com，備註放規格摘要，完整規格（JSON）存在 Products 的 `Specs`、來源網頁在 `SourceUrl`。FA 鏡頭官網只有系列頁（沒有單一型號），內部型號留空請自己補。**選型計算用的分頁也會同步**：遠心鏡頭寫進「遠心鏡頭」分頁，相機寫進「GigE」「USB3」分頁（Camera Link 等不在選型範圍）。相機的像元尺寸官網大多沒有，取得順序是：官網表格 → 自己型錄裡同款感測器 → 程式內建的常見感測器對照（會在「資料來源」欄標註「依感測器型號推定，請核對」，請對照原廠規格書確認）→ 都沒有就留空，選型計算會略過這些相機並在型錄狀態列提示數量，填上像元尺寸後就自動納入。重複按只會補新型號，已有的型號不會改你填的資料，請不要太頻繁執行並遵守對方網站使用條款

- **選型計算（跟客戶洽談時用）**：「選型計算」分頁把相機解析度、鏡頭焦距/WD/視野、飛拍拖影三種計算整合在同一頁，客戶講一個數字就填一個，每個欄位一改就即時重算。計算是一條鏈：需求 → 相機（所需像素 = 檢測範圍 ÷ (精度 ÷ 單個特徵像素)，規則同 CCD_camera：長邊 ≥ 所需長邊、短邊 ≥ 所需短邊，依畫素取最接近需求的 3 款建議，同畫素 GigE 優先，點卡片即可選用）→ 鏡頭（可切換 **FA 鏡頭 / 遠心鏡頭**：FA 自動算出焦距 F = 感測器 × WD ÷ 視野、遠心自動算出倍率 = 感測器 ÷ 視野，並直接寫進「焦距 / 倍率」欄位，可手動改（標示「手動」，按 ↺ 回到自動）；型錄建議就用這個欄位的值搜尋，列出前 3 名，點卡片即可選用）→ 實際視野 ÷ 相機像素 = 空間解析度（可選短邊或長邊為基準，預設短邊；焦距/倍率也以同一邊計算）→ 飛拍。最小檢測精度可選公差方向：**± 正負**（以輸入值計算）、**+ 只能多**、**− 只能少**（單邊公差帶只有一側，量測誤差要落在帶寬中間，以輸入值 ÷ 2 計算）；存回案件時精度會帶正負號（例如 `+2`），案件管理手動輸入也可以這樣寫。每個結果底下都用小字列出代入數字的算式，「複製計算摘要」也會附上完整計算過程，方便自己檢查跟客戶對接。右側「檢查結果」會馬上列出算不過或前後矛盾的地方（例如相機解析度不足、客戶指定的焦距拍不滿視野、飛拍拖影超標、相機影格率跟不上產能、精度單位疑似選錯），相關欄位會標紅/標黃，並直接告訴你要改成多少才行。可以從案件帶入某組 CCD 需求，算完按「把計算結果存回此 CCD」，會更新 FOV/WD/精度/速度，並把計算摘要寫進該 CCD 的檢測需求說明（重複存只會更新同一段，不會越疊越多）；「複製計算摘要」可以直接貼給客戶或同事。相機有「介面類別」選項（全部 / GigE / USB 3.0，選項直接依自己試算表 GigE、USB3 分頁裡有的介面產生，之後分頁新增別的介面也會自動出現），選了之後「型號」下拉、相機推薦與自動選相機都只在該介面裡找。相機/鏡頭型錄現在讀**自己的試算表**：`setup` 會把原本公開型錄的 4 個分頁（GigE / USB3 / FA鏡頭 / 遠心鏡頭）欄位與內容完整複製進來（只補缺的，之後直接在試算表編修、新增型號，不會被覆蓋），計算頁按「↻ 重新讀取型錄」即可套用；「＋ 補齊公開型錄」可以隨時把公開型錄新增的型號補進來。相機區另有「客戶指定品牌」「客戶指定產地」兩個選項（客戶說「要日本鏡頭」「不要中國相機」時直接篩掉）：品牌取自各型錄分頁的「原廠名稱」欄，選項依型錄裡有的自動產生，同時篩相機與鏡頭（建議、型號下拉、自動選用都只在符合的範圍裡找）；產地優先依品牌對照（Basler/Allied Vision/Schneider→德國、FLIR/Cognex→美國、海康/MindVision/大恆/華睿→中國、Sony/Computar/Tamron/Kowa/Moritex→日本等，寫在 calc.js 的 `BRAND_ORIGIN_RULES`，可自行增修），對不上的再用產品資料庫(Products)裡該型號填的「產地」。按「匯入德鴻官網」時，約 1000 筆德鴻遠心鏡頭的規格（倍率、WD、景深、遠心度、光圈、MTF、相機接口、各靶面視野）也會寫進「遠心鏡頭」分頁、可直接被選型使用（官網沒有解析度 MP 值，依支援的最大靶面估算：1.1"→20、1"→12、其他→5）；自己的分頁讀不到時才退回讀 `config.js` 的公開型錄，兩邊都沒有就改用手動輸入相機規格、FA 鏡頭以標準焦距推算。輸入值會記在瀏覽器，切到別頁再回來還在

- **下次追蹤說明**：除了下次追蹤日，客戶現在還有「下次追蹤說明」（Customers 分頁的 NextFollowUpNote 欄，需重新部署並執行 setup 補欄位）——記下這次進度到哪、下次要做什麼。「追蹤完畢」視窗、客戶新增/編輯表單、各處「改」（只改日期與說明、不會多一筆聯繫紀錄）都能填；沒填說明就儲存時會提醒一次。說明會以黃底小標籤顯示在客戶管理、案件列表、案件詳情與業務行事曆的追蹤日下方（滑過可看全文）、同步到 Google 日曆行程的說明欄，也會出現在工作日報的「下次追蹤」那一行。　**追蹤視窗上方的「本案資料」**：「追蹤完畢 / 改」視窗最上面會列出這間客戶與這個案件的資料——案件編號、狀態、緊急程度、應用 / 待測物 / 軟體、案件聯絡人與電話、終端客戶、業務 / FAE、客戶聯絡人、電話（可直接點擊撥號）與 Email（可點擊寄信），以及最近 3 筆聯繫紀錄（有案件時優先列該案件的），打電話前一眼就能看到、也方便接續上次進度；聯絡人欄預設帶案件的專案聯絡人。　**「本次需要洽談 → 下次洽談內容」流程**：在編輯客戶（或「改」）寫的「下次洽談內容」，到下次追蹤時會顯示成業務行事曆的「本次需要洽談」，打開「追蹤完畢」視窗時也會放在最上方當這次的洽談重點；按完成後視窗下方的「下次洽談內容」是留給再下一次的（預設空白，可按「沿用本次內容」帶過去）。還沒寫過洽談內容時，業務行事曆「本次需要洽談」只顯示提示（客戶備註已在旁邊的「…」，不重複顯示）；追蹤視窗則在「本次需要洽談」的位置改列一行灰色的「客戶備註」（僅供參考）。
- **預約時間**：除了下次追蹤日，客戶現在還可以記「預約時間」（Customers 分頁的 NextFollowUpTime 欄，HH:mm 純文字，需重新部署並執行 setup 補欄位）——跟客戶約了時間點就填，沒約就留空。「追蹤完畢 / 改」視窗、編輯客戶、新增客戶、客戶頁建立案件的表單都有時間欄；日期後面會顯示時間（例如 2026-10-13 09:30），業務行事曆與客戶管理同一天內依預約時間先後排序（沒時間的排後面），工作日報的「下次追蹤」也會帶時間。同步到 Google 日曆時，有預約時間就是有時間的行程（預設 1 小時，說明欄寫預約時間與洽談內容），沒填就維持整天行程；日期或時間改了，日曆行程會跟著更新（整天與有時間互換時會刪掉重建）。
- **客戶直接建立案件**：客戶管理每間客戶的操作列有紫色「建立案件」按鈕，按下會跳到案件管理的「建立新案件」，自動帶入客戶名稱、專案聯絡人、聯絡電話與目前登入的業務，並提示接著填寫案件內容（產品應用、待測物件、軟體、需求細節、CCD）後按「建立案件」。　編輯客戶資料視窗裡也有「建立案件」按鈕：不用跳頁，直接在客戶頁跳出建立案件表單（客戶、聯絡人、電話、業務、緊急程度已帶入；軟體名稱不在資料庫時會問是否新增；有案件編號預覽），一次填好案件內容並設定下次追蹤日與說明，按「建立案件並設定追蹤」就同時建好案件與追蹤；CCD 需求、相關公司可勾選建立後開啟案件頁補上。
- **案件編號（專案名稱）**：案件編號由「使用軟體名稱-待測物件-產品應用-客戶名稱」組成，所以建立案件時這三項一定要填（前端與後端都檢查，空白會被擋下並提醒），表單上會即時預覽組出來的專案名稱，有 NA 就代表還有欄位沒填。輸入錯誤時，案件詳情標題旁有「✏️ 修改專案名稱」：要輸入新名稱並經過兩次確認（提醒改名可能讓公司內部已登記的資料對不上），後端會同步更新 Cases、CCD 需求、相關公司、聯繫紀錄、價格紀錄裡的案件編號；新名稱不能和既有案件重複，也不能包含 ' " < > \ / ? # % 符號。
- **業務行事曆（schedule.html，導覽列「案件與客戶」底下）**：每天上班照著這頁做。上方有緊急程度（高/中/低）、追蹤範圍（今天與已逾期 / 3 / 7 / 30 天內 / 全部）、排序（緊急程度優先或追蹤日優先）與關鍵字篩選，並顯示已逾期、今天要追蹤、3 天內、未建案件待追蹤、進行中案件的數量。①「我的行事曆」是內建行事曆（見下一條「個人工作區」），客戶的下次追蹤也會自動出現在裡面；②「需要追蹤、但還沒建立案件的客戶」（沒有進行中案件、有設定下次追蹤日），每筆有「追蹤完畢 / 建立案件 / 改日」；③「已建立的案件」列出所有進行中案件（不含已結案），帶出客戶的緊急程度與下次追蹤日並標色，有「查看案件 / 追蹤完畢 / 改日」。資料與案件管理共用同一份暫存，追蹤進度都記在客戶身上。　**案件緊急程度**：案件現在有自己的「緊急程度」（高/中/低，建立與修改案件都能選，列表有標籤，舊案件視為中；Cases 分頁新增 Urgency 欄，需重新部署並執行 setup），行事曆③的案件用它排序。工作清單預設「先依追蹤日（逾期最前面），同一天再依緊急程度」，也可切成緊急程度優先。**④ 今日已完成的工作（工作日報）**：整理選定日期（預設今天）按過「追蹤完畢」記下的聯繫紀錄——客戶、聯絡人、方式、案件、結果、下次追蹤日——成可直接複製貼到工作日報的文字（可勾「只看我自己」、文字框可先修改），按「複製」即可。　**「本次需要洽談」欄**：②、③的清單把「下次追蹤說明」獨立成一欄（黃底粗體顯示完整內容，沒寫時提示去「改日」補上），下方小字是這間客戶「上次聯繫」的日期、方式與結果（最近一筆聯繫紀錄）；原本的「客戶備註」是公司本身的備註，留在旁邊當參考，不再和本次洽談內容混在一起。
- **詢價暫存清單**：查看產品時按「加入詢價暫存清單」可以一次累積多個要詢價的產品，清單最多保留 48 小時（過期自動清空），可以手動延長或清空；按「產生合併詢價信文字」會把所有品項合併成一份格式化的詢價信文字，如果全部品項是同一個供應商信箱，還會自動建立 Gmail 草稿
- 在「案件管理」建立新案件，等於發需求單資訊給 FAE。**客戶名稱為必填，且一定要是已經存在的客戶**（後端也會擋，不是只有畫面擋）：邊打字邊有下拉建議，如果打的名字不在清單裡，欄位失去焦點時會自動跳出小視窗讓你順便建立客戶資料，不用切分頁去客戶管理重打一次，建立後案件才能送出。業務、FAE 一樣有自動建議+快速新增。「相關公司」可以按「+ 新增相關公司」加入這個案件牽涉到的其他公司（例如同一個案子由設備商 A 做機台、終端客戶 B 使用、還有另一家協力廠 C 一起處理），各自標記角色（設備商/代理商/終端客戶/其他），存在獨立的 `CaseCompanies` 分頁；案件編號會自動照「軟體名稱-待測物件-產品應用-客戶名稱」組成，重複的話自動加流水號；「檢測需求」可以按「+ 新增CCD」加開多組相機的規格，各自獨立填寫也能個別刪除，存檔後可以直接在試算表的 `CCDRequirements` 分頁用案件編號查到每一組的詳細內容；案件詳情頁可以上傳檢測規章等附件，會存到你的 Google 雲端硬碟並列出連結，也能個別刪除；案件詳情按「📇 客戶聯繫紀錄」可以直接跳到客戶管理頁查看這間公司的聯繫紀錄。案件列表可以關鍵字+狀態搜尋，也可以用網址帶 `?company=公司名稱` 只顯示跟那間公司相關的案件（客戶管理頁「相關案件」按鈕就是這樣連過去的）、或帶 `?caseId=案件編號` 直接開啟某個案件的詳情，案件資料本身也能修改或刪除
- **導覽列分類**：分頁按鈕功能變多，改成分類的下拉選單——「業務工具」（產品搜尋/詢價、選型計算、報價系統）、「案件與客戶」（案件管理、客戶管理）、「系統」（登入紀錄、人員管理、帳號管理；後兩者只有 admin 看得到）。滑鼠移到分類上會展開子項目，點分類名稱本身會直接去該分類的第一頁

- **個人資料**：每頁右上角「個人資料」可改自己的密碼（需輸入目前密碼，新密碼至少 6 字），以及姓名、電話、電子郵件、生日；帳號本身與身分不能自己改（由管理員在帳號管理調整）

  - **轉真人**：客人說「真人 / 小編 / 業務…」，或問到你勾選「交給專人回答」的問題（價格 / 報價、訂購、樣品測試 / 專案評估、運費 / 交期、客訴 / 退換貨 / 維修，關鍵字與「請客人先留下的資料」都可改）→ 回覆轉真人文字、首頁備忘錄通知有「BOT 設定」權限的同事（附之前的對話）、暫停機器人 N 分鐘；備忘錄刪除 = 恢復機器人。
  - **其他設定**：專人服務時間（可只在服務時間以外由機器人回）、語氣 / 稱呼 / emoji / 行數、歡迎詞與常用按鈕、AI 多模型依序備援（Gemini / Claude / OpenAI 相容）、網站視窗外觀與「允許嵌入的網站」白名單、嵌入碼、對話紀錄與小編接手（網站訪客可在後台直接回覆）、測試聊天（不通知、不留紀錄）、清除對話資料（只有系統管理員）。
- **AI 模型：每組指定用在哪些功能**（BOT 設定 → 🧠 AI 模型）：可以設定最多 8 組 AI（Gemini / Claude / OpenAI 相容，各自取名，例如「預設」「爬蟲」），每組勾選要用在 **整個系統 / LINE 機器人（含網站客服視窗）/ AI 文案 / 小助理（員工助理）/ 向量**。每個功能只會用一組（勾在另一組會自動移過去）；沒勾的功能用「整個系統」那組；用的那組失敗時依清單順序備援，最後是系統共用的 `GEMINI_API_KEY`。向量只能指定給 Gemini 或 OpenAI 相容的組（Claude 沒有 embedding）。畫面下方會列出「目前每個功能實際用哪一組」，也可以用「測試」按鈕對每組發一句話確認金鑰。另可設定「每個問題最多查幾輪資料」（1～12，預設 6），調高讓複雜問題查得更完整，但會多花 AI 費用。舊設定自動視為「第一組 = 整個系統」。
- **個人工作區：行事曆 / 工作清單 / 備忘錄（每個帳號各自獨立，可分享）**：行事曆（`CalEvents`）、工作清單（`Todos`）、備忘錄（`Memos`）都是**每個帳號各自一份**，登入就能用自己的，不受「功能區塊」權限限制。
  - **分享對象**（建立或編輯時選）：只有自己（預設）／ 指定的人 ／ 自訂群組 ／ 全部同事。**被分享的人只能查看**；修改、刪除只有擁有者（系統管理員可處理別人「分享出來」的資料）。沒分享的資料連系統管理員也看不到。舊的備忘錄「分享給所有人」自動視為分享給全部同事。
  - **群組**由系統管理員在「系統 → 帳號管理 → 群組與行事曆」建立（群組名稱 + 成員）。刪除群組不會刪資料，只是分享給該群組的就沒有人看得到（改分享對象即可恢復）。
  - **行事曆**：業務行事曆頁的「我的行事曆」有清單 / 月曆兩種檢視、「我的 / 別人分享給我的」篩選、新增 / 編輯 / 刪除（全天、有時間、跨天）。**客戶的「下次追蹤」會自動寫進操作者（負責人）自己的行事曆**（標示「客戶追蹤」，預設只有自己看得到；負責人可以在提醒裡加上「誰看得到」，例如有保密協議的客戶只給指定的人；同一位負責人改期不會改掉這個設定，換了負責人就回到只有新負責人看得到），改日、追蹤完畢、公司改名、不再追蹤、刪除客戶都會同步；`setup` 會把既有的追蹤日一次性放進內建行事曆（負責人 = 該客戶進行中案件的業務，找不到就放第一位管理員）。**Google 日曆同步改成選用**（預設關，管理員在帳號管理的「群組與行事曆」勾選才會另外寫進部署帳號的 Google 日曆）。
  - **工作清單**：導覽列「案件與客戶 → 工作清單」與首頁小卡；項目有期限、優先度（高 / 中 / 低）、備註、分享對象，勾選完成（已逾期標紅）。
  - **升級前建議先備份試算表**（檔案 → 建立副本）；`setup` 只會新增分頁 / 欄位，不會刪除或改寫既有資料。
- **知識庫分流與向量檢索（客服機器人）**：知識庫每筆有 **大分類 / 主題 / 備註（寫給 AI 看的分流提示，客人看不到）**，新增 / 修改 / 匯入時自動計算向量（`BotVectors` 分頁，沿用 BOT 設定的 AI 金鑰：Gemini `gemini-embedding-001` 或 OpenAI 相容 `text-embedding-3-small`；Claude 沒有 embedding，會提示改用別家）。「BOT 設定 → 知識庫 → 🧭 搜尋流程與向量」可選：**直接向量（預設）／先用中繼資料縮小範圍再向量／只用中繼資料（不用向量）／兩種都做、結果一致才回答**，並可調**向量分數閥值**（0～1，預設 0.6，低於閥值的段落不採用；全部低於就走「找不到答案」流程）、取前幾段、指定 embedding 提供者；有「補算向量」「全部重算」與「🔎 搜尋測試」（顯示每種模式找到的段落與分數，方便調閥值）。向量算相似度在機器人伺服器（Vercel）記憶體裡，不需要外部向量資料庫；沒有可用的 embedding 時自動退回關鍵字檢索。
- **計算問題（選型計算）**：客服機器人與員工助理遇到計算問題（例如「100×80 mm 視野、精度 20 µm 要用什麼相機鏡頭」）**不會自己心算**，一定呼叫 `calc_selection` 工具（`linebot/src/calc.ts`，公式與網站「選型計算」完全相同，已用網站實際算出的 8 組案例、184 個數值逐項比對一致）。回覆固定順序：①「我整理你的需求」（每個參數與單位）→ ②「我自己補上的假設，請確認」（單位 µm / mm、公差 ± / 只能多 / 只能少、每特徵 5 px、短邊為基準、FA 或遠心…）→ ③ 計算結果與算式 → ④ 建議相機 / 鏡頭型號與提醒；**缺必要資料（檢測範圍、精度）就不算，先反問**。型錄來自產品資料庫（相機 GigE / USB3、FA 鏡頭、遠心鏡頭），**不含任何價格 / 供應商 / 備註**；客服版只用管理員開放給客服的產品類別。
- **資料範圍：客服只看知識庫，員工助理看得更多**：對外客服機器人**只讀你勾選的知識庫來源**（常見問答、文件、公司資訊、產品型號規格白名單，含向量），沒有任何管道連到客戶、案件、聯繫紀錄、報價、帳號、行事曆；員工助理除了同一份知識庫（全部啟用中的項目與向量，用 `search_knowledge` 查），還能依個人權限查客戶、案件、產品、行事曆等。兩邊用不同金鑰，客服金鑰呼叫員工助理的任何查詢都會被拒絕。
- **選型計算的速度與型錄來源**：客人問視野、精度、哪台相機鏡頭時，流程是「AI 把需求整理成參數 → **程式**在記憶體裡的型錄算出前三名相機與前三名鏡頭 → AI 照結果重述」，計算本身不碰試算表、不用 AI 心算。型錄在機器人伺服器快取 5 分鐘（知識庫版本號一變就重讀），而且看起來是選型的問題（視野、WD、精度、解析度、相機、鏡頭…）會在 AI 還在整理參數時先在背景載入，第一次問也不用多等。型錄有**自己的開關**（BOT 設定 → 客服設定 →「選型計算」，**預設開**），不用再為了推薦相機去打開「產品型號與規格」知識來源；型錄只有型號與規格，**不含價格、供應商、備註**。
- **每則回覆下方的「轉真人」按鈕**：客服機器人每則回覆下面都附「🙋 轉真人」（網站視窗是小按鈕；LINE 是最後一個快速回覆按鈕），客人按了就直接轉專人、首頁備忘錄通知同仁、機器人暫停；轉真人後的那則不再附按鈕。BOT 設定 → 客服設定可以關掉。
- **聊了幾段後請訪客留聯繫資料**：預設聊到**第 3 段**（BOT 設定 → 客服設定「聊到第 N 段後請訪客留下聯繫資料」，0 = 不問、最多 50）。網站視窗在那則回覆下面跳出表單（姓名、公司、電話、Email、需求；**電話或 Email 至少一個**）；LINE 沒辦法跳表單，會在回覆後面請客人直接回覆，客人說了姓名 / 電話，AI 會用 `save_contact` 記下來。每位客人只問一次（按「稍後再說」就不再問），留下的資料存在試算表 `BotLeads`、顯示在 BOT 設定新的「🧾 聯繫名單」分頁（可刪除、匯出 CSV），同時用首頁備忘錄通知有「BOT 設定」權限的同仁；同一位客人一小時最多留 5 次。
- **知識庫附圖（架構圖、示意圖）**：做得到。知識庫項目（常見問題或文件）編輯視窗新增「🖼️ 附圖」，每個項目最多 6 張，**每張要填說明**（例如「系統架構圖」）；瀏覽器會先縮到長邊 1600 px 再上傳到公司 Google 雲端硬碟的「AOI機器人圖片」資料夾（設成「知道連結的人可檢視」）。客人問到相關問題時，AI 看到參考資料標有「可附圖片」，就用 `send_image` 把圖傳給客人（一次最多 3 張，只能傳這次檢索到的資料附的圖）：**LINE 是文字後面接圖片訊息，網站視窗直接顯示在回覆裡，點圖可放大**。圖片經過機器人伺服器的 `/api/img` 轉成 LINE 吃的 JPG / PNG。文件型的項目，圖片會掛在每一段；BOT 設定可以整個關掉附圖。限制：Google Workspace 組織若禁止「知道連結的人」分享，圖片上傳會失敗並提示；員工助理目前不會傳圖片。
- **名片登入（員工助理）**：員工在 LINE 對員工助理傳**名片照片（單張或一次選多張）**，機器人用視覺模型（Gemini / Claude / GPT-4o，要用支援圖片輸入的模型）讀出姓名、職稱、公司、手機、公司電話、傳真、Email、地址、統編、網站，放進**名片收件匣**（試算表 `BotCards`，每個人各自一份），不會直接寫進客戶資料。每張回覆會列出讀到的內容，並提醒「收件匣已有重複」「沒讀到公司名稱」「這間公司已是客戶」。傳完說「**整理名片**」，助理列出清單，**確認後整批存入**：公司還不是客戶 → 新增客戶（姓名放聯絡人、手機 / 公司電話 / Email / 地址 / 統編帶入，職稱與網站放備註）；公司已是客戶（或同一批裡同公司的第二張）→ 新增為聯絡窗口；沒有公司名稱的略過留在收件匣。說「這批是 2026 台北自動化展」會把展會名稱記在每張名片與客戶備註，之後可以用來篩選；讀錯的欄位可以在確認前請助理修正，不要的名片可以請助理丟棄。需要「客戶與追蹤」**編輯**權限，管理員可在「員工助理 → 可以提出的修改」關閉；全程記在助理紀錄。
- **客服回覆前檢查知識庫根據（預設關閉）**：BOT 設定 → 📋 總覽 →「🛡️ 回覆前檢查知識庫根據」打開後，客服機器人產生回覆後會再請 AI 當「檢查員」，核對回覆裡每個事實（價格、規格、日期、規定、承諾…）是否都能在這次的參考資料（含 AI 用 `search_knowledge` 另外找到的內容；選型計算工具算出的結果視為有根據）找到根據；**沒有根據就不送出**，改成請客人找專人，「客服設定」的「找不到答案時」選直接轉專人則直接轉專人（主題「知識庫找不到根據」）。**檢查員出錯、回覆看不懂一律當作不通過**（寧可不答也不亂答）；轉真人的訊息不檢查。代價是每則回覆慢一點、多花一次 AI token，可到「🧠 AI 模型」勾選「**回覆檢查**」另外指定一組比較便宜、比較快的模型。沒通過的問題會記在「對話與小編接手」的對話紀錄（主題「回覆檢查未通過」），用來看出哪些問題缺資料、該補進知識庫。
- **知識庫版本號與記憶隔離**：後台新增 / 修改 / 刪除知識、重算向量、改客服可用來源或 AI 設定時，管理系統會換一個「知識庫版本號」，機器人每則訊息都會帶回來比對，**版本變了就馬上重讀知識庫**（不用等 5 分鐘快取，刪掉的資料不會再被找到）。客服與員工助理的提示詞都加了「之前對話裡自己說過的話不算參考資料，每次都只根據這次查到的內容回答」，要硬性擋下舊答案就打開上面的回覆前檢查。短期記憶依對象各自存放（客服每位客人一份、員工助理每位同事一份），A 用戶與 B 用戶問同一題不會互相影響；直接在試算表手動改 `BotKnowledge` 不會換版本號，最多 5 分鐘生效（建議都從網站後台改）。
- **知識庫新增 / 編輯（參照 FonegleWeb）**：BOT 設定 → 知識庫，列表是卡片（點一下開啟編輯，彈窗內有刪除；文件整份合併成一張卡，顯示段數與字數、無向量的段數）。常見問題與文件共用同一個彈窗：文件名稱、上傳 txt / md / csv / json / html / pdf、貼上內容；**✂️ 切段（向量）**可設每段字數（預設 500）與重疊字數（預設 100），「👁 預覽切段」看每段開頭與重疊部分；**🤖 讓 AI 來切**＝AI 先讀過整份文件，依主題決定在哪裡切並替每段下小標（只回傳「從第幾句切開」，不改寫內容；可選用哪一組 AI 與模型，畫面會預估 token，費用記在選的那組金鑰，內容沒改就不重切）；另有大分類、主題、備註（給 AI 看）、關鍵字、**給誰看（小助手 / 對外客服）**、啟用。編輯文件會把整份重新切段（舊段落連同向量一起換掉），儲存後自動補算向量。
- **知識庫每一筆可以設定誰看得到**：BOT 設定 → 知識庫，每筆常見問題 / 文件段落都有「**誰可以看到**」可複選——🛎️ 對外客服機器人、🧑‍💼 員工助理，**預設都開放**。只勾「員工助理」就是內部資料，客人問不到；兩個都不勾 = 兩邊都看不到。列表有「可見對象」標籤；整份文件可用「🔒 可見對象」一次設定（匯入文件時也能先選）。向量也依對象過濾，客服金鑰拿不到只給助理的內容。設定後最多 5 分鐘生效。
- **助理紀錄（備忘錄稽核）**：員工助理做的**任何事**都會記在首頁備忘錄的「🤖 助理紀錄」（每位成員每天一則，依時間持續追加）：查詢（含條件與筆數）、搜尋知識庫、選型計算、提出的修改（待確認）、確認後的執行結果、刪除、取消、**被權限擋下的嘗試**。只有有「BOT 設定」權限的人看得到；**只有系統管理員能修改或刪除**（助理自己也不能刪）。「BOT 設定 → 員工助理」可選擇只記修改、不記查詢，或整個關閉；單則超過上限會自動續寫新的一則。
- **員工助理全功能**：員工助理（LINE 與網站右下角「智能助理」）可以做網站上大部分的事，**一律依這個人的權限、再被管理員設的上限壓低**；查詢直接做，**所有新增 / 修改 / 刪除都只是「提出」，本人按確認才執行；刪除還要這個人的網站帳號本來就有刪除權限（只有系統管理員），而且助理做的每一件事都會記在備忘錄供檢查**：
  | 範圍 | 查詢 | 提出修改（需確認） |
  |---|---|---|
  | 客戶 | 搜尋客戶、客戶詳情（窗口、最近聯繫、案件）、要追蹤的客戶、聯繫紀錄 | 記錄聯繫與下次追蹤、改客戶資料、新增客戶、新增聯絡窗口 |
  | 案件 | 搜尋案件、案件詳情（含 CCD） | 建立案件、改狀態 / 緊急程度、改案件內容（聯絡人 / 需求說明 / 評估結果…） |
  | 公司知識庫 | 查客服機器人用的那份知識庫（常見問答、文件、公司資訊，含向量檢索，跟客服同一套搜尋流程與分數閥值）；每位已開通的同事都能查，不受「客服可用來源」勾選限制，只看啟用中的項目 | （唯讀，要改請到 BOT 設定 → 知識庫） |
  | 產品與詢價 | 產品搜尋與詳情（規格、相容產品）、歷史報價、詢價信文字草稿、選型計算 | 記錄報價、新增產品、改產品資料、把詢價信存成 Gmail 草稿（只存草稿、不寄出） |

- **FAE**：登入後在「案件管理」找到對應案件，評估報告有兩種做法：方式一是填寫測試結果、建議搭配產品，選好格式後按「自動產生評估單」（會一併自動產生搭配報價單，報價單的客戶類型跟格式也可以在旁邊選）；方式二是直接在「手動撰寫評估報告」欄位打字排版、調顏色字級，存草稿或選格式（PDF/HTML）後「預覽/下載」。所有產生的文件都會先進預覽視窗，確認沒問題再下載
- **業務**：案件建立後可以選格式產生需求單，一樣會先進預覽視窗，確認內容沒問題再下載，傳給 FAE 或行政窗口
- **行政窗口**：查詢產品時會自動看到「上次詢過的供應商與價格」，確認是否要重新詢價，詢價後記得按「存入價格紀錄」，下次才會自動帶出
- **業務（報價系統）**：新增品項時直接在型號欄位打字，會自動跳出符合的產品清單可以直接點選（不用背完整型號、也不怕打錯），輸入底價或牌價會自動互相換算，選客戶類型（設備商×1.3 / 一般用戶×1.5 / 自訂義自行輸入倍數）自動算出報價；加入多個品項後選好格式按「產生報價單」一樣會先進預覽視窗，確認沒問題再下載，或勾選「客戶現場展示模式」把底價/牌價隱藏起來，只顯示報價給客戶看
- **客戶追蹤/行事曆**：公司分類固定四種：**AOI同業資料 / 器材原廠 / 機構合作設備商 / 一般客戶**，另外可以標記「已交易過」與「上次交易日」（列表有「交易狀態」欄，按「編輯交易狀態」修改）；急迫性（高/中/低），列表上方可以用分類和急迫性篩選；有填「下次追蹤日」會自動加進**操作者自己的內建行事曆**（有預約時間就是有時間的行程），之後改日 / 追蹤完畢 / 不再追蹤都會同步更新或刪除同一筆；客戶列表按「相關案件」可以直接跳到案件管理只看這間公司的案件。客戶也可以直接刪除
- **客戶聯絡窗口（支援多筆）**：客戶列表本身的聯絡人/電話/Email 是「主要聯絡人」；一間公司如果有好幾個窗口（不同電話、不同信箱、不同承辦人），按客戶列表的「聯絡窗口」可以開一個小視窗新增/刪除多筆聯絡人資料，存在獨立的 `CustomerContacts` 分頁
- **客戶聯繫紀錄**：每次跟客戶聯繫完（電話/Email/拜訪），在客戶管理分頁「新增客戶聯繫紀錄」填一筆，公司名稱打好之後，「聯絡人」欄位會自動帶出這間公司的聯絡窗口清單、「所屬案件」下拉選單也會自動列出這間公司名下的案件（同一個客戶有多個案件在進行時，可以指定這筆聯繫是針對哪一個）下方「聯繫紀錄列表」可以照公司篩選、查看歷史紀錄、刪除，有指定案件的話會顯示案件編號連結，點下去直接跳到那個案件的詳情頁

|---|---|---|
| `robot-loader.js` | 官網每一頁（`<script src="robot-loader.js"></script>`，`index.html` 已加） | 只負責載入 GitHub 上的 `robot-widget.js`，**建好後幾乎不用再改** |
| `robot-widget.js` | 這個 GitHub 儲存庫根目錄（經由 jsDelivr 載入：`https://cdn.jsdelivr.net/gh/OMG8787/cetus_salesWeb@main/robot-widget.js`） | 小機器人本體與選單設定，**常常改的是這支**。改完 `git push`，**jsDelivr 對 `@main` 最多快取 12 小時**，要馬上生效就開 `https://purge.jsdelivr.net/gh/OMG8787/cetus_salesWeb@main/robot-widget.js` 清快取；或把 `robot-loader.js` 的 `ref` 改成 tag / commit 編號（不會被快取卡住，但每次發版要改一次） |

設定一次：`robot-loader.js` 最上面填 `user`（GitHub 帳號）、`repo`（儲存庫）、`ref`（分支，預設 `main`）。`robot-widget.js` 最上面 `CONFIG`：

- `chatUrl`：**機器人伺服器（Vercel）的網址**，例如 `https://你的專案.vercel.app`。**這不是 LINE 的 Webhook**（LINE 官方帳號的 Webhook 才是 `https://你的專案.vercel.app/api/cs`）；網站客服視窗用的是同一個網域，程式會自己接 `/api/widget/…`，所以只填到網域，不要加路徑。後台「BOT 設定 → 🌐 網站客服視窗」要啟用，並把官網網址（例如 `https://你的官網網域`）填進「允許嵌入的網站」。
- `items`：選單項目。`action: 'chat'` 開智能客服、`'contact'` 開客服視窗並跳出留聯繫資料表單（資料進「🧾 聯繫名單」）、`'human'` 直接轉專員；`fallbackUrl` 是客服視窗載不到時改去的網址（沒填就自動隱藏那個項目）；也可以用 `url` 直接連到別的頁面，或自己寫 `onClick`。
- 另外有位置、主題色、提示氣泡、不顯示的頁面（`hideOnPaths`）。

小機器人用 Shadow DOM，不會被官網原本的 CSS 影響；手機上客服視窗是全螢幕時，小機器人會先讓位。客服視窗本體是機器人伺服器上的 `widget.js`，小機器人載入它時會隱藏它自己的圓形按鈕（`data-launcher="false"`）。

## 之後可以擴充

程式碼已經整理成「加新功能不用大改架構」的樣子：

- **後端(Code.gs)**：所有 API 動作都註冊在檔案最上面的 `ROUTES` 物件裡。新增功能只要 1) 寫一個 `handleXxx(body)` 函式 2) 在 `ROUTES` 加一行 `xxx: { auth: true, fn: handleXxx }`，`doPost` 完全不用改
- **前端**：每個分頁是獨立的 `.html` + `.js`，呼叫 `callApi('你的action', {參數})` 就會自動打到後端對應的 handler；如果想要示範模式也測得到，在 `demo.js` 的 `handleDemoApi` switch 裡加一個對應的 case 就好；`common.js` 放的是所有分頁共用的東西（登入檢查、載入遮罩、文件預覽彈窗），只有真的每一頁都要用到的邏輯才放進去，其他都留在各分頁自己的 `.js`

延伸功能舉例：
- 報價歷史紀錄：加一張 `Quotes` 分頁，`handleGenerateQuoteDoc` 產生文件前先 `appendObjectRow` 存一筆
- 若要調整權限：在 `Code.gs` 的 `ACTION_PERM` 修改該動作的 [功能區塊, 等級]（r 查看 / w 新增修改 / d 刪除）；要新增功能區塊，加進 `PERM_BLOCKS` 並在前端 `common.js` 的 `ACCESS_BLOCKS` / `BLOCK_LABELS` 加上，選單按鈕與頁面 `<body>` 加 `data-block`
- 若想要更漂亮的介面，可以之後把某個分頁的 `.html`/`.js` 換成 Vue/React 等框架寫，只要 `callApi()` 的呼叫方式不變，其他分頁跟後端完全不用改

目前結果：後端 17 個檔案 835 項檢查、機器人伺服器 102 組測試，全部通過；官網小機器人 + 網站客服視窗另用無頭 Chrome 搭配模擬伺服器逐項操作驗證；選型計算另與網站 `calc.js` 逐項比對（`linebot/test/calc-compare.ts`）。畫面部分用無頭 Chrome 在示範模式（`DEMO_MODE = true`）逐頁操作驗證（行事曆 / 工作清單 / 分享 / 群組 / BOT 設定 / 文案 / 助理浮窗，含深色模式）。

**更新到新版的步驟**：① 備份試算表 → ② 把最新 `apps-script/Code.gs` 整份貼進 Apps Script（專案只有這一個檔案）→ ③ 執行 `setup` → ④ 部署 → 管理部署作業 → 新版本 → ⑤ 前端推到 GitHub Pages（自動）→ ⑥ 機器人伺服器（`linebot/`）重新部署到 Vercel：`cd linebot` 後執行 `npx.cmd vercel --prod`（詳見 linebot/README.md；API 上限 12 支）（若是用上傳資料夾建立的專案，要重新上傳；用 GitHub 連線的會自動更新）。

## 疑難排解

- **前端顯示「連線失敗」**：檢查 `config.js` 的 `API_URL` 是否貼對，以及 Apps Script 是否已部署為「所有人」可存取
- **登入一直失敗**：確認 Users 分頁的密碼雜湊值是用 `generatePasswordHash` 產生、且帳號欄位沒有多餘空格
- **選 PDF/Word 格式產生失敗，訊息是找不到範本**：檢查 Config 分頁的 `TemplateDocId_Requirement` / `TemplateDocId_Evaluation` / `TemplateDocId_Quote` 是否為正確的 Google 文件 ID；如果不想處理範本，選 **HTML** 格式即可，不需要範本
- **登入後跳轉某一頁變成空白/功能不動**：確認 GitHub repo 裡 `frontend` 資料夾**所有檔案**都有上傳，尤其 `common.js`、`demo.js`、`config.js` 這三個是每一頁都要用到的共用檔案，漏傳的話該頁會整個失效
- **切換分頁後要重新登入**：登入狀態存在瀏覽器的 sessionStorage，正常情況下同一個瀏覽器分頁切換不會登出；如果每次都要重登，檢查是不是用無痕視窗或瀏覽器設定封鎖了網站資料儲存

## 客服視窗：手動發表單與網站流量

- **手動發表單**：BOT 設定 → 對話與小編接手，選一位網站訪客後，回覆欄旁有「📇 填基本資料 / 📷 找相機 / 🔍 找鏡頭」按鈕，訪客視窗會立刻跳出對應表單（再發一次會關掉舊的、開新的）。只能發給網站訪客，LINE 客人不行。
- **小編與訪客即時對話**：訪客視窗每 2 秒、後台開著對話時每 3 秒更新一次；小編不按「轉真人」也能直接插話。
- **網站流量**：BOT 設定 → 📈 網站流量。每個載入客服視窗的頁面回報一次、之後每 60 秒回報停留（頁面在背景分頁不計時），同一個瀏覽器算一位訪客，不記個資；資料存在試算表 `BotVisits` 分頁（超過 2 萬筆自動刪最舊的 2000 筆）。部署後才開始記錄。
